FILE / 03Readout

Three signals to investigate—not assume.

These are analytical prompts derived from the scenario generator, not claims about a real business.

01 / RESPONSE

Response speed varies sharply by source.

Referral averages 59.1 minutes to first response; Paid Social averages 555.0 minutes. Check routing, staffing windows, and ownership rules before changing channel investment.

02 / CONVERSION

Referral leads have the strongest sample win rate.

The fictional cohort shows 41.7% won for Referral versus 10.4% for Paid Social. Compare qualification and project fit before treating that gap as channel quality.

03 / FOLLOW-UP

An exception list makes the KPI operational.

The 66-row sample queue prioritizes open leads with a response-SLA breach or an overdue next action. It is a follow-up prompt, not an automated customer message.

FILE / 04Analyst action

Trace the delay before moving the budget.

In a real lead operation, use the scorecard to choose where to investigate—not to declare a winning or losing source.

  1. Audit first-response workflow by channel. Compare assignment, notification, and staffing timestamps to find where delay enters the process.
  2. Validate stage definitions and denominators. Confirm what counts as a consultation, proposal, won project, and duplicate enquiry with stakeholders.
  3. Work the open-lead queue with safeguards. Confirm ownership and next action in an authorized CRM; do not send bulk messages from an unverified portfolio metric.
FILE / 05Method, QA & limitations

Reproducible logic; deliberately bounded claims.

SQL, Python tests, and explicit metric definitions keep the scorecard auditable.

Data

192 deterministic, fictional lead records across four sources and four cities. No customer names, email addresses, or phone numbers.

Metric rules

First response within SLA is ≤ 240 minutes. Consultation and won rates use all source leads. Open-lead exceptions are measured at the fixed 31 Aug 2026 cutoff.

Tools

SQLite-compatible SQL · Python · regression tests · Google Apps Script queue refresh · Power BI-ready DAX measures.

QA correction

The first SQL draft used < 240, incorrectly excluding a response at exactly four hours. The boundary regression exposed the mismatch: Website showed 14 on-time leads instead of the expected 21. The rule was fixed to <= 240; the corrected build passes all four tests.

Interpretation limit

Every difference is a property of the generated scenario—not Livspace, a real employer, or the home-interior market. No causal claim is made.
